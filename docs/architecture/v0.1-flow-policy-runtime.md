# V0.1 Flow → Policy → ExecutionPlan slice

This is the first executable architecture slice of Commeatus.

## Boundary

Input: a canonical `FlowContext`.

Output: an immutable `ExecutionPlan`.

The slice intentionally does **not** perform socket I/O, proxy handshakes, DNS resolution, eBPF attachment, TProxy interception, configuration parsing, or adaptive learning.

## Pipeline

```text
platform/importer metadata
        ↓
   FlowContext
        ↓
    Matcher
        ↓
  PolicyEngine
        ↓
 PolicyDecision
        ↓
 ExecutionPlan
```

## Policy authority

Authority is fixed from strongest to weakest:

```text
UserHard
> Safety
> Compatibility
> Adaptive
> Default
```

Rules are stably ordered by authority when the policy engine is built. Flow evaluation then performs one linear first-match scan over the precedence-compiled rule sequence. This keeps authority ordering out of the per-flow hot path while preserving source order within each tier.

Adaptive policy therefore has no authority to override user hard rules or safety rules.

## Concept separation

`Reject` is an action. It is not an endpoint.

`Direct` is an endpoint. It is selected by a route action.

This distinction is intentionally encoded in Rust types so compatibility formats cannot force legacy concepts such as a "block outbound" into the native runtime model.

## Current matchers

The V0.1 typed matcher supports:

- UID
- package identifier
- exact domain
- domain suffix with label-boundary matching
- exact IP address
- destination port
- TCP / UDP
- network kind
- `All`, `AnyOf`, and `Not` composition

CIDR, process identity, interface-specific policy, indexed/compiled matcher structures, and richer domain canonicalization are later slices.

## Current endpoint/action set

Endpoints:

- `Direct`

Actions:

- route to endpoint
- reject with a typed reason

Proxy endpoints are deliberately deferred until the endpoint capability model is defined.

## Stability and power properties established here

- policy evaluation is deterministic;
- policy decisions are fixed before execution;
- a lower-authority subsystem cannot override higher-authority policy;
- compatibility syntax does not enter the core model;
- rejection cannot masquerade as an outbound endpoint;
- precedence is compiled outside the per-flow hot path;
- the slice has no background workers, timers, polling, or persistent state.
