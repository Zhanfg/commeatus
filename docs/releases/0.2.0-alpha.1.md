# Commeatus v0.2.0-alpha.1

This is the second public alpha of Commeatus.

The release keeps the native flow/policy architecture from v0.1 and adds the first UDP data path, compiled domain filtering, an independent DNS failure domain, Android/Linux capability probing, and a CI-verified eBPF attach-point prototype.

## Included binaries

- Linux x86_64
- Android arm64 (`aarch64-linux-android`, NDK/API 29 build baseline)

## Major changes

### SOCKS5 UDP

- `UDP ASSOCIATE` is now supported.
- UDP destinations go through the same `FlowContext → PolicyEngine → ExecutionPlan` path as TCP.
- The UDP relay is bound to its TCP control connection.
- Client UDP source is locked to the control peer / first accepted source.
- Replies are accepted only from remote endpoints previously contacted by the association.
- UDP fragmentation is deliberately unsupported in this alpha.

### DNS engine

Domain resolution now lives in `commeatus-dns` rather than protocol handlers.

Resolution order:

```text
Hosts override → bounded cache → ordered resolver chain → system resolver
```

The current network resolver is still the operating-system resolver. The new boundary is intended to accept DoH/DoT/DoQ later without changing SOCKS5 or HTTP handlers.

Configuration can load DNS hosts files:

```text
hosts ./dns/hosts.txt
```

Hosts assets are compiled transactionally with the configuration.

### Compiled domain filtering

Configuration can load blocklists:

```text
blocklist ./rules/ads.txt
```

Accepted alpha forms include:

```text
0.0.0.0 ads.example
tracker.example
||telemetry.example^
@@||api.telemetry.example^
```

The source is normalized and compiled into native immutable domain sets. Allow exceptions suppress only the blocklist match; they do not force a routing action.

### Platform/eBPF boundary

New command:

```bash
commeatus platform
```

It reports non-destructive evidence for TUN, TPROXY, eBPF, BTF and bpffs.

The repository also contains CI-compiled `cgroup/connect4` and `cgroup/connect6` eBPF programs. They currently return allow and perform no live interception. There is no BPF loader in this release.

## Security notes

This alpha still has no inbound proxy authentication. Non-loopback listeners remain rejected unless `allow-public-listen true` is explicitly configured.

UDP replies are restricted to previously contacted remote endpoints, and referenced hosts/blocklist files are bounded and compiled before a candidate runtime can replace the Last Known Good snapshot.

## Not in this release

- SOCKS5/HTTP authentication
- UDP fragmentation/reassembly
- TUN interception
- live TPROXY rule installation
- eBPF loader/maps/redirection
- KernelSU/Magisk packaging
- Shadowsocks/VLESS/Trojan/Hysteria2/TUIC native outbounds
- DoH/DoT/DoQ/Fake-IP
- remote rule providers
- Clash/mihomo/sing-box import or API facade
- adaptive/Smart routing
- final low-power event-driven executor

The current release is intended as a tested architectural/data-plane milestone, not a production replacement for mature proxy cores.
