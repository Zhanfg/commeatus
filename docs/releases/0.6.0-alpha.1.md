# Commeatus v0.6.0-alpha.1

This is the sixth public alpha of Commeatus.

The release moves Commeatus from an application-facing proxy daemon toward its Android Root target: verified DNS-over-TLS and explicit secure resolver chains are now joined by native TCP and UDP TPROXY ingress. Transparent traffic still enters the same flow/policy/outbound runtime as SOCKS5 and HTTP traffic, so interception does not become a second routing engine.

## Included binaries

- Linux x86_64
- Android arm64 (`aarch64-linux-android`, NDK/API 29 baseline)

The Android binary is the native core/daemon binary. KernelSU/Magisk packaging is not part of this alpha.

## Major changes

### Typed DNS answers and explicit secure resolver chains

The DNS failure domain now carries typed answer metadata instead of reducing resolver output to a bare address list. Secure resolver fallback is explicit configuration rather than an implicit downgrade path.

Persistent verified DNS-over-TLS is available as a native resolver. The DoT path keeps certificate/server-name verification mandatory and reuses the transport boundary rather than teaching the routing core TLS mechanics.

`examples/dot-resolver.conf` demonstrates the v0.6 resolver form.

### Native transparent TCP ingress

`listen tproxy-tcp <ip:port>` accepts Linux/Android Root TPROXY TCP traffic and recovers the original destination from the accepted socket. The recovered destination is converted into the ordinary native `Target` and evaluated through:

```text
TPROXY TCP
    ↓
FlowContext
    ↓
PolicyEngine
    ↓
ExecutionPlan
    ↓
OutboundRegistry
```

The ingress therefore does not own DIRECT/proxy selection and does not bypass native policy.

### Native transparent UDP ingress

`listen tproxy-udp <ip:port>` adds the corresponding UDP path.

Linux/Android original-destination ancillary metadata is decoded through safe `nix` wrappers. The daemon itself remains `#![forbid(unsafe_code)]`.

Each intercepted UDP datagram is evaluated independently through the existing native policy and datagram-provider boundaries. DIRECT UDP and native proxy datagram providers—including Trojan UDP—can therefore be selected without protocol-name branches in the transparent listener.

Unsupported proxy UDP still fails locally and never silently mutates policy into DIRECT.

### Source-correct transparent UDP replies

Transparent UDP cannot reply from the interception listener address: the application expects the response to come from the original remote `IP:port`.

v0.6 therefore emits replies through a bounded cache of `IP_TRANSPARENT` UDP sockets bound to the exact original source socket address. Both source address and source port are preserved.

Client state, route count, reply-socket count, event drain bursts and idle lifetime remain bounded. Readiness tokens come from a listener-wide allocator so separate transparent clients cannot collide in one poll set.

A newly observed transparent UDP client is now rolled back immediately if its first outbound send fails, rather than occupying a client slot until idle expiration. The production path also avoids an `expect()` for that state transition.

### Android Root TCP + UDP lifecycle helper

`scripts/android-root-tproxy.sh` installs/removes the v0.6 TCP+UDP interception state.

The helper owns only Commeatus-specific state and includes:

- IPv4/IPv6 TPROXY capability probing;
- dedicated mangle chains;
- policy-routing marks/tables;
- selectable Android UID interception range;
- root-owned daemon bypass;
- explicit cleanup of installed state.

`examples/android-root-tproxy.conf` is the matching combined transparent-listener configuration.

The older TCP-only helper remains available as a narrower reference path.

## End-to-end verification

The standard GitHub Actions gate now includes privileged kernel-path verification, not only unit mocks.

### TCP namespace proof

A Linux network namespace test installs real TPROXY TCP rules/policy routing, generates intercepted traffic and verifies original-destination routing through the native runtime.

### UDP namespace proof

The UDP proof creates isolated network namespaces and veth interfaces, installs real UDP TPROXY and policy routing, sends traffic as a selected Android-style UID, and verifies that:

- Commeatus receives the original destination;
- native policy executes before outbound creation;
- the echoed response payload is preserved;
- the client observes the exact original remote source `IP:port`;
- TPROXY/mark rules record intercepted packets;
- cleanup removes Commeatus-owned chains and policy routes.

The same CI also performs a privileged nonlocal transparent UDP source-bind smoke test.

## Security / stability notes

- transparent TCP/UDP are ingress adapters, not alternate policy engines;
- no selected proxy path silently falls back to DIRECT;
- daemon code remains safe-Rust-only; original-destination CMSG decoding uses audited safe wrappers;
- transparent UDP client state and source-correct reply sockets are bounded and idle-expiring;
- failed first sends do not leave empty transparent-client state behind;
- root interception bypasses the root-owned Commeatus daemon to avoid self-looping;
- helper cleanup is scoped to Commeatus-owned chains/routes;
- verified TLS/DoT retains mandatory certificate and server-name validation;
- secure resolver fallback must be configured explicitly rather than silently downgrading.

See ADR-0013 through ADR-0016 for the accepted v0.6 DNS and transparent-interception decisions.

## Release gates

The exact release commit must pass:

- Rust formatting;
- workspace check;
- architecture guard;
- Clippy with warnings denied;
- complete unit/E2E suite;
- privileged TCP and UDP TPROXY bind/namespace E2E;
- release build and CLI/config smoke;
- explicit Rust 1.85 all-target compatibility;
- Android arm64 NDK/API-29 build and ELF verification;
- eBPF prototype compilation/section verification;
- Linux + Android release packaging with SHA-256 verification.

The release workflow repeats these gates on the exact `main` commit before creating the prerelease and tag.

## Still not in this release

- TUN interception
- live eBPF loading, maps, redirect or policy execution (compile prototype only)
- KernelSU/Magisk module packaging
- Shadowsocks, VLESS, Hysteria2 or TUIC
- endpoint groups, health selection, load balancing or Smart/adaptive routing
- DoH, DoQ or Fake-IP
- inbound/upstream SOCKS5 or HTTP proxy authentication
- Clash/mihomo/sing-box configuration import or compatible API
- remote rule-provider refresh
- final low-power global TCP executor
- shared/multiplexed Trojan datagram carrier pooling

The next line should build on this stable interception boundary rather than moving routing logic into TPROXY. Android Root packaging, additional protocol providers and adaptive/network-control work can remain independent consumers of the same native policy/runtime model.
