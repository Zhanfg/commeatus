# Commeatus v0.5.0-alpha.1

This is the fifth public alpha of Commeatus.

The release turns the transport and outbound boundaries established in v0.4 into the first native encrypted proxy protocol with both stream and datagram execution. Trojan now runs natively over verified TLS for TCP CONNECT and UDP ASSOCIATE, while the runtime gains a reusable event-driven datagram provider boundary that later UDP-capable protocols can attach without teaching SOCKS5 or the core route model protocol-specific behavior.

## Included binaries

- Linux x86_64
- Android arm64 (`aarch64-linux-android`, NDK/API 29 baseline)

## Major changes

### Protocol providers own stream handshakes

Outbound stream protocols are now provider objects rather than a central enum switched by the registry.

```text
ExecutionPlan
    ↓
EndpointId
    ↓
OutboundRegistry
    ↓
Protocol provider
    ↓
TransportSession
```

The runtime asks a provider for capabilities and lets that provider perform its own protocol handshake. Routing, DNS and endpoint selection remain outside the protocol implementation.

This removes a central protocol switch before adding more native protocols and keeps the compatibility surface from becoming the runtime model.

### Native Trojan CONNECT over verified TLS

Trojan is the first encrypted native proxy protocol in Commeatus.

The native endpoint form is:

```text
endpoint edge trojan tls 203.0.113.10:443 trojan.example change-me
```

The configuration compiler converts the raw password into the protocol verifier before the active runtime is built. Stream CONNECT uses the shared Trojan verifier/address wire primitives over the existing verified `TlsTransport`.

The native TLS path still:

- validates certificate identity and SNI;
- has no insecure / skip-verification switch;
- separates connection `SocketAddr` from TLS identity;
- uses bounded connect, handshake and plaintext buffering;
- keeps rustls and encrypted socket ownership inside `commeatus-transport`.

### Datagram associations are logical sessions

SOCKS5 UDP execution no longer owns a hard-coded DIRECT socket path. The datagram runtime now has an explicit logical association/execution boundary and an outbound-owned factory.

A single SOCKS5 UDP ASSOCIATE may lazily maintain multiple policy-selected outbound routes:

```text
SOCKS5 UDP ASSOCIATE
       ↓
policy per datagram
       ↓
DatagramRouteSet
  Endpoint -> DatagramExecution
       ↓
OutboundRegistry
```

Routes are bounded and created on demand. Unsupported proxy UDP fails locally and never silently mutates policy into DIRECT.

The previous fixed 500 ms UDP-control polling path is gone. Control closure, client UDP readiness and outbound readiness are driven by `mio::Poll`.

### Stream and datagram providers attach independently

A proxy endpoint can now attach a stream provider and an optional datagram provider independently.

```text
ProxyEndpointConfig
├─ stream protocol + transport
└─ optional datagram provider
```

UDP capability is derived from the actual datagram provider attachment. There is no protocol-name allowlist in `OutboundRegistry` and no fake UDP capability for protocols that do not implement one.

This is the extension point that Trojan UDP uses and later datagram-capable protocols must reuse.

### Readiness-driven framed TLS carrier

`commeatus-transport` now exposes an internal framed TLS session for protocols that exchange discrete records over a verified TLS stream.

The transport continues to own:

- rustls state;
- encrypted `mio::net::TcpStream`;
- certificate/server-name verification;
- encrypted read/write service;
- dynamic READABLE/WRITABLE registration.

Writable interest is enabled only while rustls has ciphertext to flush. Once drained, it is removed rather than leaving a continuously writable fd registered and waking the event loop.

Protocol code sees only plaintext framed I/O, never the raw encrypted socket or rustls connection.

### Native Trojan UDP

Trojan UDP is implemented as a dedicated datagram provider over the framed TLS carrier.

The provider sends a normalized Trojan UDP ASSOCIATE preface:

```text
<56-byte SHA224 hex verifier> CRLF
CMD = 0x03
ATYP = IPv4
ADDR = 0.0.0.0
PORT = 0
CRLF
```

Actual destinations live in each following UDP frame, so one logical association may send to multiple IPv4, IPv6 or domain targets.

The frame parser supports:

- 16-bit big-endian payload lengths;
- incomplete frames retained across TLS reads;
- multiple coalesced frames in one plaintext burst;
- zero-length UDP payloads;
- strict CRLF and address framing validation.

A proxied domain remains a domain in the Trojan UDP frame. It is not resolved through the local DIRECT DNS engine first.

Trojan UDP state is explicitly bounded:

- 64 pending frames;
- 512 KiB pending protocol bytes;
- 128 KiB decrypted receive buffering;
- one readiness source per Trojan datagram execution;
- existing bounded per-association outbound route count remains in force.

No background Trojan worker or periodic UDP timer is introduced.

## End-to-end verification

The release adds real local E2E coverage for Trojan stream and datagram execution.

Trojan TCP proves:

```text
HTTP CONNECT inbound
→ policy-selected Trojan endpoint
→ native Trojan CONNECT handshake
→ verified TLS transport
→ local Trojan TLS mock
```

Trojan UDP proves the complete path:

```text
SOCKS5 UDP inbound
→ policy-selected proxy endpoint
→ DatagramRouteSet
→ OutboundRegistry datagram factory
→ TrojanDatagramProvider
→ verified framed TLS
→ local Trojan TLS mock
```

The UDP proof uses the destination `opaque-trojan-udp-target.invalid` and verifies that the upstream mock receives that domain unchanged, demonstrating that proxy-selected UDP domains are not leaked into local destination DNS.

The server also deliberately:

- checks the verifier and `CMD=0x03` preface;
- checks the normalized `0.0.0.0:0` initial target;
- splits one response frame across two TLS writes;
- coalesces a second complete frame behind the first;
- sends the second frame with a zero-length payload.

The client reconstructs and emits both datagrams independently through the real readiness loop.

## Security / stability notes

- raw Trojan passwords are transformed at configuration compilation; Debug output does not expose verifier bytes;
- malformed Trojan framing fails the affected datagram path rather than panicking the process;
- unsupported proxy UDP never falls back to DIRECT;
- TLS verification remains mandatory on the native path;
- proxied domains remain opaque to local DIRECT DNS;
- protocol, transport, policy and datagram lifecycle ownership remain separate;
- datagram queues, receive buffers and route growth are bounded;
- fixed 500 ms SOCKS5 UDP wakeups were removed;
- framed TLS WRITABLE interest is transient to avoid idle busy-wakeup behavior.

See ADR-0006 through ADR-0012 for the accepted v0.5 protocol/datagram decisions.

## Release gates

The exact release commit must pass:

- Rust formatting;
- workspace check;
- Clippy with warnings denied;
- complete unit and E2E suite, including native Trojan TCP and UDP;
- release build and CLI/config smoke;
- explicit Rust 1.85 all-target compatibility;
- Android arm64 NDK/API-29 build and ELF verification;
- eBPF prototype compilation/section verification;
- Linux + Android release packaging with SHA-256 verification.

The release workflow repeats those gates on the exact main commit before creating the prerelease and tag.

## Still not in this release

- Shadowsocks, VLESS, Hysteria2 or TUIC
- upstream/inbound proxy authentication
- endpoint groups, health selection or load balancing
- DoH / DoT / DoQ / Fake-IP
- TUN interception
- live TPROXY installation
- live eBPF loading, policy maps or redirection
- KernelSU/Magisk module packaging
- Clash/mihomo/sing-box configuration import or compatible API
- remote rule-provider refresh
- adaptive/Smart routing
- final low-power event-driven global TCP executor
- shared/multiplexed Trojan datagram carrier pooling

The next development line should move to another independent subsystem boundary—secure DNS or safe interception—rather than making SOCKS5, Trojan or the outbound registry the owner of additional cross-cutting behavior.
