# Commeatus v0.4.0-alpha.1

This is the fourth public alpha of Commeatus.

The release establishes the transport layer that encrypted proxy protocols will reuse. TLS is now a verified transport/security capability below the existing proxy-protocol handshakes instead of a feature owned by SOCKS5, HTTP CONNECT, or the core route model.

## Included binaries

- Linux x86_64
- Android arm64 (`aarch64-linux-android`, NDK/API 29 baseline)

## Major changes

### Transport-owned sessions

Outbound protocols no longer receive or return a raw `TcpStream` as their execution contract.

```text
ExecutionPlan
    ↓
EndpointId
    ↓
OutboundRegistry
    ↓
ProxyProtocol handshake over Read + Write
    ↓
TransportSession
    ↓
transport-owned full-duplex relay
```

`TcpTransportSession` owns TCP-specific cloning and half-close behavior. This keeps `TcpStream::try_clone()` out of proxy protocol code and leaves room for carriers that cannot be cloned like a raw socket.

### Verified native TLS transport

`TlsTransport` uses rustls 0.23 with the ring crypto provider.

The native default path:

- validates the configured TLS server identity;
- uses the embedded WebPKI server-root set;
- keeps the upstream `SocketAddr` separate from TLS `ServerName` / SNI;
- applies bounded connect and handshake timeouts;
- bounds rustls plaintext buffering;
- does not expose an insecure / skip-verification switch.

A custom `ClientConfig` constructor exists for deterministic local tests and future explicit trust-policy implementations. The native configuration path remains verified by default.

### Protocol × Transport composition

The existing SOCKS5 and HTTP CONNECT outbound protocol handshakes now run over either plain TCP or TLS without TLS-specific branches in protocol code.

Current native forms:

```text
# v0.3-compatible implicit TCP
endpoint edge socks5 127.0.0.1:1081

# explicit TCP
endpoint edge-explicit socks5 tcp 127.0.0.1:1081

# verified TLS: connection address and certificate identity are separate
endpoint secure socks5 tls 203.0.113.7:443 proxy.example
```

The upstream connection address remains a literal socket address. This release does not introduce hidden proxy-bootstrap DNS behavior.

### Readiness-driven TLS relay

After the proxy protocol handshake succeeds, `TlsTransportSession` owns the rustls state and switches the carrier/client sockets to nonblocking mode.

The relay uses readiness notifications rather than a periodic timer:

- read/write interests are registered only while useful work exists;
- plaintext pending buffers are bounded;
- TLS state has one owner rather than an `Arc<Mutex<...>>` shared between relay threads;
- valid TLS `close_notify` shutdown is preserved;
- an unclean network EOF is not silently treated as a valid TLS close.

### Android native dependency toolchain

Adding ring exposed a real cross-compilation gap in the previous Android CI: Cargo knew the NDK linker, but native C/assembly build scripts did not.

The repository now configures the same NDK/API-29 toolchain for:

- `CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER`
- `CC_aarch64_linux_android`
- `AR_aarch64_linux_android`

The Android arm64 build and release-package dry run both pass with rustls/ring enabled.

## Verification

The release line requires:

- Rust formatting
- workspace check
- Clippy with warnings denied
- complete unit and E2E suite
- release build and CLI/config smoke
- explicit Rust 1.85 all-target compatibility
- Android arm64 NDK/API-29 build and ELF verification
- eBPF prototype compilation/section verification
- Linux + Android release-package dry run with SHA-256 verification

TLS-specific deterministic tests cover:

- explicitly trusted local certificate + matching server name succeeds;
- the same trusted certificate + wrong server name fails;
- TLS full-duplex relay performs a clean `close_notify` shutdown;
- legacy TCP, explicit TCP, and TLS endpoint configuration forms compile;
- invalid TLS server identity rejects the candidate configuration;
- endpoint encryption capability is derived from the transport.

A cross-layer E2E proves:

```text
HTTP CONNECT inbound
→ policy selects Proxy(endpoint)
→ SOCKS5 outbound protocol
→ verified TLS transport
→ local TLS SOCKS5 mock
→ echo server
```

The target is `opaque-tls-target.invalid`; the upstream SOCKS5 peer observes the original domain and reaches the echo server independently, preserving the no-local-destination-DNS property of proxy routes.

## Security / architecture notes

- TLS is transport/security behavior, not a proxy-protocol property.
- Certificate verification is mandatory on the native default path.
- There is no native `insecure` / `skip-verify` compatibility shortcut in this release.
- Connect address and certificate identity are distinct values.
- Native TLS currently trusts embedded WebPKI roots, not Android/Linux user-added enterprise roots.
- Unsupported endpoint UDP capability still never degrades to DIRECT.
- The core still sees only opaque endpoint identity.

See ADR-0004 and ADR-0005 for the accepted transport decisions.

## Not in this release

- Trojan
- VLESS
- Shadowsocks
- Hysteria2 / TUIC
- proxy UDP execution
- endpoint groups / health selection / load balancing
- Android/Linux platform trust-store import
- client certificates / mTLS
- certificate pinning
- explicit ALPN policy / ECH
- TUN interception
- live TPROXY installation
- live eBPF loading/maps/redirection
- KernelSU/Magisk packaging
- DoH / DoT / DoQ / Fake-IP
- Clash/mihomo/sing-box import or compatible API
- adaptive/Smart routing
- final low-power global executor

The next protocol milestone should place the first encrypted native proxy protocol on top of the transport boundary already established here, rather than reintroducing routing/DNS/TLS ownership inside protocol code.
