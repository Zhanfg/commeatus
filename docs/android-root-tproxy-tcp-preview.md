# Android Root TCP transparent preview (v0.6 development)

This is the first Commeatus slice intended to carry ordinary Android application traffic rather than only explicit SOCKS5/HTTP clients.

## What this preview actually does

```text
selected Android app TCP
        ↓
iptables OUTPUT mark
        ↓
policy route -> loopback
        ↓
TPROXY PREROUTING
        ↓
Commeatus tproxy-tcp listener
        ↓
original destination IP:port
        ↓
FlowContext -> Policy -> ExecutionPlan
        ↓
DIRECT or native proxy endpoint (including Trojan/TLS)
```

The TPROXY listener uses `IP_TRANSPARENT` / `IPV6_TRANSPARENT`. The root helper uses dedicated mark/table/chain names and removes only its own state.

## Important limitation

**UDP is not intercepted yet.** DNS/QUIC/game/voice UDP therefore stays outside this transparent preview. Do not describe this build as a full-device or leak-proof proxy. Transparent UDP is the next required v0.6 slice.

## Requirements

- Android arm64 Root shell (KernelSU/Magisk/APatch style root is sufficient if the shell has the required capabilities)
- kernel/netfilter TPROXY support
- `ip`, `iptables`, and `ip6tables` when IPv6 is enabled
- the Android arm64 Commeatus binary built from this branch
- a real native endpoint configuration; the checked-in example uses TEST-NET data and cannot reach the Internet unchanged

The helper defaults to IPv6 enabled. If the device cannot install IPv6 TPROXY, it fails rather than silently turning IPv6 off. `COMMEATUS_IPV6=0` is an explicit diagnostic override only.

## Configure

Copy `examples/android-root-tproxy-tcp.conf` and replace:

```text
endpoint edge trojan tls 203.0.113.10:443 trojan.example change-me
```

with the real Trojan server socket address, certificate name, and password.

The example listens on:

- SOCKS5 debug port `127.0.0.1:1080`
- IPv4 TPROXY `127.0.0.1:12948`
- IPv6 TPROXY `[::1]:12948`

## Start

From a root shell:

```sh
chmod 755 ./commeatus ./scripts/android-root-tproxy-tcp.sh
./commeatus check --config ./android-root.conf
./scripts/android-root-tproxy-tcp.sh start ./android-root.conf ./commeatus
```

The helper starts the daemon with `nohup`, records its PID/log under `/data/local/tmp/commeatus-root`, probes TPROXY in unhooked test chains, then installs routing. If routing setup fails, it kills the newly started daemon and rolls back its own rules.

Check state:

```sh
./scripts/android-root-tproxy-tcp.sh status
cat /data/local/tmp/commeatus-root/commeatus.log
```

Stop and restore routing:

```sh
./scripts/android-root-tproxy-tcp.sh stop
```

## Default interception scope

The preview marks TCP generated by UID range `10000-999999`, covering ordinary application UIDs while leaving the root-owned Commeatus process outside its own interception path. Override when testing a narrower set:

```sh
COMMEATUS_UID_RANGE=10123-10123 ./scripts/android-root-tproxy-tcp.sh start ./android-root.conf ./commeatus
```

The helper bypasses loopback, IPv4 link-local/multicast, and IPv6 loopback/link-local/multicast before marking. Application traffic that reaches the listener is still governed by the native Commeatus rules; the shell script does not choose DIRECT vs proxy.

## Recovery

If the daemon is killed externally, remove the routing state before troubleshooting:

```sh
su -c './scripts/android-root-tproxy-tcp.sh remove'
```

The script intentionally does not flush generic mangle tables or delete unrelated policy rules.

## Not yet provided

- transparent UDP
- automatic boot service / KernelSU module packaging
- privilege drop to a dedicated service UID
- SO_MARK on every daemon outbound socket
- Android network-change watcher
- captive portal special handling
- per-package name resolution (the first preview selects kernel UID ranges)
